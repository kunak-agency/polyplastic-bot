# synthetic-pulse-generate — текст синтетического ответа новичка на пульс

Версия: **v1** (2026-10-23). Только для генерации тестовых данных, в продукте не используется.
Где используется: офлайн-генератор по `data/generator-spec.yaml` и `data/personas.yaml`
(пишет Implementer/ML). Выход — поле `text` записи в `data/synthetic/responses.jsonl`.
Модель: **не та связка модель+промпт, что размечает `/flags`** (см. `generator-spec.yaml →
generation_model`).

## Strategy

Zero-shot с ролевой карточкой персоны. Примеры не даём намеренно: few-shot сузит
разнообразие, и тексты станут похожи на примеры из `flags-classify.md`, то есть утекут в
тест. Разнообразие обеспечивают temperature 0.9, стиль речи персоны и длина из спецификации.

## Переменные

| Плейсхолдер | Откуда |
|---|---|
| `{gender}`, `{age_band}`, `{site}`, `{department}`, `{position}`, `{shift}`, `{speech_style}`, `{address_form}` | персона |
| `{day}`, `{question}` | точка пульса |
| `{scales_summary}` | код: «задачи 5/10, руководитель 8/10» или пусто |
| `{must_mention}` | код: человеческие описания активных флагов, например «нет доступа к учётной записи 1С»; пусто — «ничего» |
| `{must_not_mention}` | код: описания остальных категорий одной строкой |
| `{length}` | `empty` \| `one_word` \| `short` (до 15 слов) \| `normal` (15–50 слов) |
| `{typos}` | `да` \| `нет` |
| `{lexicon}` | список слов площадки из спецификации |

Имя персоны в промпт **не передаём**: в тексте ответа оно не нужно, и так в датасет не
попадёт ничего похожего на ПДн.

Для `length=empty` генератор LLM не вызывает и пишет `""`.

## A) System prompt

```text
Ты пишешь вымышленный ответ нового сотрудника на вопрос бота в рабочем мессенджере. Это синтетические данные для тестирования. Человек вымышленный.

Пиши как живой человек в чате: от первого лица, разговорно, без канцелярита, без приветствий и подписей. Не упоминай, что ты ИИ, и не упоминай «флаги» и «категории».

Не пиши имён, фамилий, телефонов, e-mail, адресов, номеров документов. Если нужно назвать человека, пиши роль: «мастер», «наставник», «руководитель», «коллега».

Верни ровно один JSON-объект: {"text": "…"}
```

## B) User message

```text
Кто ты: {gender}, {age_band} лет, площадка {site}, {department}, {position}, смена: {shift}.
Как пишешь: {speech_style}. Обращение бота к тебе: {address_form}.
День работы: {day}. Вопрос бота: «{question}».
Твои оценки в этом опросе: {scales_summary}.

Обязательно скажи о проблеме (своими словами, без названия категории): {must_mention}
Не упоминай вообще: {must_not_mention}

Длина: {length}. Опечатки: {typos}. Подходящие слова: {lexicon}.
```

## C) JSON-схема

```json
{"type": "object", "properties": {"text": {"type": "string"}}, "required": ["text"], "additionalProperties": false}
```

## D) Guardrails (в генераторе)

- Ответ содержит `@`, `+7`, 10+ цифр подряд → перегенерировать.
- `one_word` длиннее 2 слов, `short` длиннее 15 → перегенерировать (не больше 2 раз,
  потом обрезать).
- Дедупликация по cosine > 0.9 (спецификация).
- Проверить вручную выборку: прозвучал ли `must_mention` и не прозвучал ли запрещённый
  флаг. Утечка запрещённого флага портит gold-метки, такие записи выкидывать.

## G) Model settings

temperature 0.9, top_p 0.95, presence_penalty 1.0, max_tokens 160 (из `generator-spec.yaml`).
