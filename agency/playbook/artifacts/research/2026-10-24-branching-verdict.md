## 2. Вердикты

**Q1 Модель.** Линейный список сообщений в блоке + ветка как короткая подпоследовательность
(≤ 2 сообщений), привязанная к кнопке и всегда возвращающаяся в поток. Не граф и не «реплика как шаг
с родителем».
- Время у двух сущностей разное: блок идёт по расписанию, ветка уходит мгновенно по callback.
- Слияние неявное, действие `end_block` прерывает поток.
- Циклов нет, глубина 2: у кнопок в ветке своих веток нет.
- Если новичок не нажал, ничего не делаем. Для опросов — правило r70.
- Запасной вариант на случай более глубоких веток — `goto_block`.

**Q2 Что в ветке.**
- Сообщения (≤ 2) и терминальные кнопки.
- Действия: escalate, handoff, set_field, set_flag, send_file, open_free_text, end_block, goto_block.
- Флаги только булевы, без «переменных» в интерфейсе.
- Правила после опроса — отдельная сущность `outcomes` (Should).

**Q3 UI.** Правая панель шага: под кнопками вкладки веток, рядом живое превью диалога («телефон»).
- Таблица шагов только для обзора, мини-графа нет.
- Колонки таблицы: День · Время · Площадки · Тип · Текст · Кнопки · Ветки «2/3» · Статус.
- Предупреждения (публикацию не блокируют): вложение без файла, нет варианта для площадки, пустая ветка.
- Ошибки (блокируют публикацию): кнопка без подписи, подпись > 18 символов, > 7 кнопок в ряду,
  handoff без получателя, goto в никуда.
- Тестирование: «Отправить себе в МАКС» и «Пройти этот путь».
- Что взять у других:
  - Enboarder — условия по профилю, вычисляемые при отправке;
  - Typebot — превью рядом;
  - Manychat — статистика кнопок;
  - n8n и Voiceflow — публикация с diff;
  - Rasa — подтверждение удаления.
- Чего избегать: холст «экран → стрелка», обязательную ветку «иначе».

**Q4 Импорт.**
- Детерминированный парсер, отчёт с номерами строк, «Принять / Исправить» по неоднозначностям.
- Excel служит форматом миграции и экспорта, основной редактор — кабинет.
- Экспорт в формат заказчика со скрытым `step_key`. Повторный импорт сопоставляет по ключу и
  показывает diff.

**Q5 Медиа.** Медиатека «Имя · превью · тип · файл по площадке · используется в N шагах».
- Импорт создаёт 19 записей-заглушек, у каждой до 3 файлов по площадкам.
- Переименование автоматически заменяет ссылки. Удалить можно, только если запись используется в 0 шагах.
- Отправка в MAX через `POST /uploads` с кэшем токена.

**Q6 Версии.** Уже отправленное доживает по снимку своей версии. Публикация «для активных»
действует только на неотправленные блоки.
- Payload кнопки ссылается на версию.
- Модалка публикации показывает последствия цифрами.
- По умолчанию «только для новых», если кнопки удаляются или переименовываются. «Для активных» —
  если правится текст.

**Q7 Аналитика.**
- Бейдж на кнопке: доля и абсолют.
- На шаге: ответили, не ответили, медиана времени ответа.
- На ветке: сколько обращений она дала. Порог анонимности ≥ 5.

**Q8 Защита за 1–2 минуты:**
1. Импорт Excel → отчёт → клик по «r19 письмо HR».
2. Добавить ветку-причину «Пропуск» с обращением.
3. «Опубликовать для активных», показать последствия.
4. Телефон: машина времени → кнопка → обращение в кабинете.
5. Бейдж на кнопке обновился.

## 3–5. Модель данных, эскиз панели, порядок работ

- Модель: Scenario{blocks, rules}, Block{key, when, tags, condition, kind bot|hr_task, required,
  messages, no_answer, survey.outcomes}, Message{text ty/vy по тегам, alt_text, attachment, question,
  buttons}, Button{label, kind, opens_free_text, branch}, Branch{messages ≤ 2, actions, then, goto},
  Action{escalate|handoff|set_field|set_flag|send_file|open_free_text}, Outcome, LiveMessage со
  снимком.
- Must (~6 ч):
  1. парсер и отчёт;
  2. исполнение веток и действий, payload с версией;
  3. медиатека и вложения по площадке;
  4. панель шага: вкладки веток, селекты действий, «если не ответил», валидация, «Отправить себе» и «Пройти путь»;
  5. публикация с diff и счётом «затронет N»;
  6. бейджи статистики;
  7. условие «по отмашке» и площадка из «Когда».
- Should:
  - превью «телефон»;
  - multi;
  - outcomes;
  - экспорт в Excel и повторный импорт с diff;
  - goto_block.
- Не делать: граф, выражения, глубину больше 2, правку веток в таблице, пиксельно точное превью.

## 6. Прямые замечания

- Циклы и слияние — не проблема: ветка всегда возвращается в поток.
- Ветка «иначе» не обязательна.
- «Следующая реплика» — это порядок сообщений, а не ветка. Парсер, который считает её веткой,
  сломает 10 строк из 68.
- Правила после опроса (r57) — отдельная сущность outcomes.
- Импорт должен поймать письмо HR (r19) и авторские альтернативы (r8).
