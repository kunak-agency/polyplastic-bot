## Суть

ПОЛИПЛАСТИК: группа компаний, производитель полимерных трубопроводных систем, 33 завода (hh.ru).
Численность 8 500 взята из условия кейса, публично не подтверждена. Площадки в кейсе: GrPP и
Luzhniki (офис), GTP (производство, смены).

Формулировка кейса на сайте хакатона: бот уже есть, его нужно «пересоздать в MAX и расширить
AI-функциями: RAG по непубличной базе, корпоративный стиль, панель управления для рекрутёров».
Поэтому в демо и питче показываем «было → стало», а не «бот с нуля».

Корсик — ИИ-помощник адаптации в MAX:
- ведёт новичка по таймлайну D−3…D+90 от даты выхода, учитывая метки площадок и смены;
- отвечает по регламентам (ПВТР, презентации, Excel-таймлайн) с цитатой пункта, а если
  источника нет, отказывает и передаёт вопрос человеку;
- собирает пульс-опросы «живым сообщением»;
- выделяет красные флаги F1–F10 и направляет их HR, руководителю или в СБ;
- HR правит сценарии в web-кабинете, там же видит новичков, обращения и аналитику.

Лицо решения (решение 1 ресерча): **конструктор сценариев (таймлайн из Excel) + RAG с цитатой и
эскалацией**. Голос остаётся усилителем: контур (а) «голосовые в MAX» идёт в демо, контур (б)
«звонок-сессия» — только при зелёном стоп-кране.

## Ограничения платформы MAX (факты из ресерча, блок A, schema v0.0.33)

| Ограничение | Следствие для нас |
|---|---|
| REST `https://platform-api2.max.ru`, токен в `Authorization` без `Bearer`; нужен корневой CA Минцифры | свой `http.Client` с CA через `WithHTTPClient` (SDK сам CA не подкладывает) |
| События: webhook (443, доверенный CA, самоподписанные запрещены с 25.05.2026) **или** long polling `GET /updates` (`timeout` ≤ 90 с, `marker`); одновременно нельзя; long polling «не для production» | long polling, домена с TLS нет. Для голосовых UX-спека требует webhook — см. противоречие в `02-open-questions.md` |
| Серверной отложенной отправки нет | свой планировщик `scheduled_events` + поллер — ядро продукта |
| Первое сообщение без `bot_started` не описано (ни разрешено, ни запрещено) **[проверить]** | вход только по персональной deep-ссылке; формат ссылки спорный (см. 02) |
| Deep link: payload ≤ 128 символов, длиннее обрезается; по клику приходит `bot_started` с `payload`, `user_id`, `chat_id` | invite-токен случайный, без ПДн |
| ≤ 2 сообщения/с в один диалог; ~30 rps глобально (на токен или на платформу — не уточнено) | очередь отправки по чатам, пауза 0,6 с, ≤ 20 rps суммарно; обработка 429 — в нашей обёртке |
| Текст ≤ 4 000 символов с разметкой; разметка без списков и таблиц, переносы в коде схлопываются | «карточка»: картинка + 3–5 строк + кнопки; списки вручную `1️⃣`/`—` |
| Только inline-клавиатура, 7 типов кнопок; ≤ 7 в ряд (≤ 3 для `link`/`open_app`/`request_*`); до 210 кнопок, 30 рядов; reply-клавиатуры нет | шкала 1–10 — два ряда по 5 |
| `callback` → `message_callback`; ответ `POST /answers` с `message` (редактирует исходное) или `notification` | «живые опросы» и «ответил — зафиксировал» |
| `image` + `video` (до 12) сочетаются с клавиатурой; `file` — одно, с клавиатурой; `audio`/`contact`/`sticker` — единственное вложение | |
| После `POST /uploads` возможен `attachment.not.ready` | SDK ретраит 3 раза (1 и 2 с) |
| Бот не создаёт чаты, не добавляет участников (`POST /chats/{id}/members` ограничен, по skill удалён 30.09.2026) | handover через групповые HR-чат и СБ-чат, куда бота добавил человек (`bot_added` → `chat_id`) |
| Бот без `read_all_messages` в группе может не видеть сообщений без упоминания **[проверить]** | выдать боту админа; иначе — ответ HR через кнопку «Ответить» или через кабинет |
| «Прочитано» в диалогах недоступно; есть `dialog_muted`, `bot_stopped` | метрики — «нажал/ответил», не «прочитал» |
| `AudioAttachment`: `payload.url`, `payload.token`, `transcription: string \| null` (v0.0.33). Формат файла, TTL ссылки, условия появления транскрипции не описаны **[проверить]** | во вложенной в Go SDK схеме v0.0.30 поля нет — парсим сырой JSON |

## Ловушки

1. **Первое касание.** Нельзя строить демо на «бот пишет первым», пока тест не прошёл. Базовый
   путь — ссылка/QR из оффера → `bot_started`. Если `user_id` без Start не работает, подаём это как
   фичу безопасности: «бот пишет только тем, кто подтвердил себя».
2. **Планировщик — наш.** Перенос даты выхода пересчитывает недоставленные события без дублей
   (идемпотентность по `event_id`). Пропущенные шаги при позднем подключении собираются в одно
   сообщение «Что вы пропустили». Условия шага вычисляются при отправке, а не при старте.
3. **Лимит 2/с на диалог.** Пакет D−3 (5 сообщений) и гид D0 (6 сообщений) без очереди упрутся
   в 429.
4. **Пользовательский текст в разметке.** `*`, `_`, `<` ломают `format` — экранировать.
5. **Редактирование сообщения < 24 ч** (UX-спека, правило 2; в ресерче не подтверждено
   **[проверить]**). Старше — новое сообщение.
6. **Сентимент ≠ флаг.** «Нет доступа к 1С неделю» имеет нейтральный тон, но это флаг F2.
   Эскалацию решает код, а не LLM.
7. **F5/F9 никогда не уходят линейному руководителю.** Конфликт с руководителем не уходит этому
   руководителю. Это проверяется тестом, а не промптом.
8. **Галлюцинации и выдуманные пункты.** Gate по порогу реранкера (старт 0.3, калибровать), JSON
   с обязательными `clause_id`, проверка цитат кодом. Ловушка «ДМС» обязана дать отказ.
9. **T-lite: `temperature` и `presence_penalty` 1.0 обязательны в каждом запросе** (карточка
   модели). Забытый параметр тихо ухудшает ответы, поэтому они зашиты в клиент.
10. **OCR скана ПВТР.** Номера пунктов не должны быть «придуманы», значит нужна ручная вычитка
    23 страниц. В агентной команде это гейт человека или отдельная проверка по golden set.
11. **«On-prem» в питче и RunPod на демо.** Ресерч строит аргумент «данные не покидают контур»
    на локальной GPU, а наш LLM работает на поде RunPod, это внешний хостинг. Формулировку для
    питча решаем явно (см. 02).
12. **Синтетика.** Генерировать одной моделью или промптом, классифицировать другой, иначе
    метрики завышены. На питче честно говорим: данные синтетические, судья — локальная модель.
13. **Эмоции по голосу не делаем** (EU AI Act ст. 5(1)(f) с 02.02.2025; Dusha WA 0.53 на
    реальной речи). Голос без идентификации — обычные ПДн по 152-ФЗ, не биометрия по 572-ФЗ
    (письмо Минцифры, не нормативный акт).
14. **152-ФЗ.** С 01.09.2025 согласие — отдельный документ. Кнопка «Согласен» в боте — уведомление
    и фиксация, а не замена документа. Ст. 86 ТК и ст. 16 152-ФЗ по первоисточнику не сверены
    **[проверить в КонсультантПлюс до 25.10 09:00]**.
15. **Экономика.** «70 %» — цель заказчика, а не факт; на демо показываем измеренный deflection.
    HR-часы на новичка (J = 4 ч) — главное допущение, его закрывает только кейсодержатель.
16. **Gallup «12 % считают онбординг отличным»** подтверждён только вторичными агрегаторами,
    использовать с пометкой или не использовать.
