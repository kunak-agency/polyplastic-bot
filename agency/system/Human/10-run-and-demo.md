# Запуск и показ на чек-поинте и защите

Как поднять всю систему одной командой, что открыть и в каком порядке показывать, и что делать, если что-то упало.

**Карта набора:** [00-index.md](00-index.md) | **Связанные:** [06-hr-cabinet-guide.md](06-hr-cabinet-guide.md), [08-decisions.md](08-decisions.md)

Источники: README («Быстрый запуск», «Сценарии для проверяющего»), `Makefile`, `docker-compose.demo.yml`, `.env.example`, `agency/pitch/deck.md` §2, `agency/pitch/checkpoint-2410.md`. Значения переменных здесь не приводятся — только имена.

## Что и зачем

Жюри смотрит критерий «Прототип»: совпадает ли заявленное с работающим. Значит, показывать надо только проверенное и заранее знать, что делать, если сеть, телефон или модель подведут.

## Поднять всё самому

**Нужно:** Docker с Compose v2 и 8 ГБ памяти для Docker, ~10 ГБ диска, `make`. Go, Node и Python не нужны.

| Команда | Что делает |
|---|---|
| `make rag-models` | один раз: скачать веса поиска и реранкера (~6 ГБ, ~10 мин) |
| `make demo` | собрать и поднять Postgres, API с ботом, сервис поиска, кабинет и демо-данные. Первый раз 5–10 мин. Сам создаёт `.env` из `.env.example` |
| `make demo-ps` | состояние контейнеров |
| `make demo-logs` | логи |
| `make demo-down` | остановить (данные остаются) |
| `make demo-clean` | остановить и удалить демо-базу |

Без `make rag-models` поиск работает только по словам, без реранкера: ответы с цитатой будут, разговорные вопросы находятся хуже.

### Адреса `make demo`

| Что | Адрес |
|---|---|
| Кабинет HR | http://localhost:18080 |
| Демо-чат | http://localhost:18080/dev/chat |
| API | http://localhost:18081/api/health |
| Поиск (RAG) | http://localhost:18093/health |
| Postgres | порт 15440 |

Порты слушают только эту машину. Меняются переменными `DEMO_WEB_PORT`, `DEMO_API_PORT`, `DEMO_RAG_PORT`, `DEMO_PG_PORT`. `DEMO_BIND` открывает кабинет в сеть (для стенда) — помните, что входа в кабинете нет.

Локальный запуск для разработки использует другие порты: Postgres 5437, API 8081, поиск 8093, кабинет 5173.

### Переменные окружения (только имена)

| Зачем | Переменные |
|---|---|
| Живой бот MAX | `MAX_BOT_TOKEN`, `MAX_BOT_USERNAME`, `MAX_CA_FILE` (сертификат Минцифры), `INVITE_LINK_FORMAT`, `INVITE_TTL` |
| Модель | `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`, `LLM_TIMEOUT`, `LLM_TEMPERATURE`, `LLM_PRESENCE_PENALTY` |
| Поиск | `RAG_BASE_URL`, `RAG_ASK_TIMEOUT`, `RAG_CORPUS` (`real` — настоящие документы, если лежат локально) |
| Групповые чаты | `MAX_HR_CHAT_ID`, `MAX_SB_CHAT_ID` |
| Дайджест | `MAX_DIGEST_USER_IDS`, `CABINET_URL` |
| Кабинет | `KB_OPERATOR_TOKEN`, `KB_MAX_UPLOAD_MB`, `MEDIA_MAX_MB` |
| Прочее | `APP_ENV`, `DATABASE_URL`, `RUNPOD_API_KEY` |

**Свой бот MAX:** вписать токен и имя бота в `.env` и снова `make demo` — бот перейдёт с подделки на настоящий MAX. **Один токен — один запущенный бот**: второй экземпляр с тем же токеном поделит сообщения. Демо-чат работает только без токена.

## Показ на чек-поинте и защите

**Формат:** настоящий MAX на телефоне через трансляцию экрана + кабинет в браузере. План Б — видео 60–90 с.

### Перед показом (за 30 минут)

- [ ] Под LLM «hackaton» запущен и отвечает (см. ниже), поиск отвечает на `/health`.
- [ ] Поднят **ровно один** API с живым токеном. Остальные стенды — с пустым токеном.
- [ ] Задан сертификат Минцифры (`MAX_CA_FILE`) — без него бот не достучится до MAX.
- [ ] Вопрос для показа проверен заранее. Если поиск работает на настоящих документах, «аванс» ищется уже в ПВТР, а не в синтетике.
- [ ] Параллельные агенты и тяжёлые процессы остановлены: под их нагрузкой первый ответ однажды шёл 24 с вместо 2,3 с.
- [ ] Если делали сброс демо-данных, новичка для демо создать заново и открыть свежую ссылку: сброс снимает привязку MAX.
- [ ] Телефон заряжен, уведомления других чатов выключены, плашка «API: работает» зелёная, видео открыто во второй вкладке.

### Сценарий показа (≈ 1:45)

| Время | Действие | Что говорим |
|---|---|---|
| 0:00 | Кабинет: «Запустить адаптацию» | «HR заводит новичка, Корсик сразу строит план по рабочим часам площадки» |
| 0:12 | «Приглашение» → телефон: ссылка → «Начать» | «QR в оффер — требование вашего ТЗ, строка 8. Бот пишет только тем, кто сам перешёл по ссылке» |
| 0:22 | Телефон: «на вы» → согласие | «Согласие до первого разговора. Нажатая кнопка превращается в итог» |
| 0:32 | Кабинет: машина времени → телефон: шаги | «Прокручиваем три дня. Каждое сообщение — по сценарию, который HR правит в Excel и в кабинете» |
| 0:50 | Телефон: вопрос по регламенту → «Подробнее» | «Ответ только с пунктом. „Подробнее“ — сам пункт дословно» |
| 1:05 | «Положен ли ДМС?» → «Передать HR» | «Этого в документах нет. Бот не выдумывает, а передаёт человеку» |
| 1:15 | Кабинет: обращение → A → «Ответить в МАКС» → телефон | «HR отвечает отсюда, новичок получает ответ с подписью и сам закрывает вопрос» |
| 1:35 | Обращение F9 | «Жалоба на коррупцию уходит только в СБ. Это правило в коде, а не в промпте» |

Если есть ещё минута: «Сценарии» → сценарий из Excel-ТЗ → отчёт импорта → ветки → «Таймлайн» → «Сделать вариант на «вы» (ИИ)». Тексты ТЗ на экране не задерживать.

### Что честно оговаривать

- Сценарий из Excel-ТЗ, дайджест и уведомления руководителю проверены на подделке MAX и в демо-чате, на телефоне — нет.
- В живом MAX не проверены голосовые, «печатает», карточки в групповые чаты HR и СБ.
- Модель — наша, на арендованной GPU. Не говорить «on-prem».

## Если упал под LLM

**Симптомы:** ответы приходят дословной цитатой без пересказа, кнопка «вариант на „вы“» правит только словарём («Машинная правка — проверьте»), дайджест — шаблоном.

**Что делать:**
1. Открыть RunPod, найти под **«hackaton»** и посмотреть статус.
2. Если он остановлен — запустить. Перед запуском свериться с ценой в час (по журналу $1,09/ч, L40S).
3. Подождать **~2–3 минуты**: столько занимает старт модели (по журналу около 2,5 мин).
4. **Адрес модели не меняется**: он привязан к поду, `LLM_BASE_URL` править не нужно.
5. Задать один вопрос для прогрева.

Под «hackaton» общий с соседним хакатоном (решение человека 23.10 — держать включённым). Если на хосте пода нет свободных GPU, под может не стартовать — такое уже было с двумя подами (`agency/LOG.md`, 23.10). Тогда показываем без модели.

### Как бот живёт без модели (проверено по коду)

| Функция | Без модели |
|---|---|
| Ответ на вопрос | дословная цитата лучшего пункта с «📄 Источник». Модель не ответила за `LLM_TIMEOUT` — тоже цитата |
| Разговорный вопрос | переформулировки нет, работает только словарь сленга: чаще отказ и «Передать HR» |
| Ловушки | отказ, как и с моделью |
| Разметка риска | только правила-слова (F5, F7, F9) и флаги вариантов опроса. Новичок ничего не замечает |
| Вариант на «вы» | словарь кода; удаление рода не работает |
| Дайджест | текст по шаблону, числа те же |
| Сценарии, опросы, напоминания, обращения, кабинет | работают как обычно |

Фраза для сцены: «Если модель не ответила, бот отдаёт сам пункт дословно — так устроен откат».

### Если упал сервис поиска

Бот пишет «Сейчас не могу проверить по документам: справочная база не отвечает…» и предлагает «Передать HR». Голосовые не распознаются. Сценарии и обращения работают.

### Если бот отвечает медленно

Через `RAG_ASK_TIMEOUT` бот сам пишет «Ищу в документах дольше обычного — пришлю ответ сюда же…» и досылает ответ. Для сцены: «Обычно это 2–3 секунды; если поиск задерживается, бот сам предупреждает».

## План Б

1. **Видео 60–90 с** этого же сценария на чистых данных. Включать сразу, если телефон или стенд не ответил за 15 секунд.
2. **Демо-чат** — тот же путь на подделке MAX, если у телефона нет сети. Честно сказать: «Это эмулятор, в живом MAX — на видео».
3. **Скриншоты**: реестр, приглашение, ответ с пунктом, отказ про ДМС, ответ HR, F9, обзор.

## Полезно знать

- **Не останавливать процессы по номеру порта.** Это правило команды: «убить всё на порту» на проброшенном порту Docker убивает сам Docker Desktop. Останавливать по имени процесса или командой `make demo-down`.
- **Docker на этой машине общий** с соседним проектом, у его VM 8 ГБ. 24.10 ночью Docker Desktop падал, вероятно от нехватки памяти при сборке образа поиска (`agency/LOG.md`, «Инцидент»). Тяжёлые образы перед показом не собирать.
- **Регламент защиты не выяснен:** Положение — 5 мин + 3 на вопросы, FAQ сайта — 3 + 2. Готовим ядро на 3 минуты и расширение до 5 (`deck.md`, раздел 0).
- **Сдача до 25.10 10:00:** код ссылкой на облако (доступ ≥ 90 рабочих дней), презентация ≤ 10 МБ, тизер, видео, выступающий в ЛК.
