# Словарь терминов

Короткие определения слов, которые встречаются в документах, в кабинете и на защите.

**Карта набора:** [00-index.md](00-index.md)

---

## Время и маршрут сотрудника

| Термин | Что значит | Пример |
|---|---|---|
| **D0** | день выхода на работу. От него считается весь маршрут | выход в понедельник 9 ноября: D0 = 9 ноября |
| **D−3, D−1** | за три дня и за день до выхода | D−3 — пакет знакомства, D−1 — напоминание о документах |
| **D+N** | N календарных дней после выхода | D+2 — опрос третьего дня, D+14 — чек двух недель |
| **Блок** | сообщения одного дня и времени. Исполняется как диалог | блок D−3 — около десятка реплик подряд |
| **Шаг** | одно сообщение блока (текст, карточка, файл, опрос, ввод ответа, задача) | «Какие документы взять» |
| **ИС** | испытательный срок. В ТЗ его последний день — D+89 | итоговый опрос в конце ИС |
| **Этап** | группа дней: до выхода, день выхода, первая неделя (до D+7), первый месяц (до D+30), ИС (до D+90), завершено | `backend/domain/scenario.go`, `StageForDay` |
| **Машина времени** | кнопка в карточке сотрудника: прокручивает его время вперёд, чтобы не ждать днями | на демо показываем 3 дня за минуту |
| **Рабочие часы площадки** | окно, когда бот начинает блоки и шлёт напоминания: пн–чт 9:00–18:00, пт 9:00–17:00, Москва | `backend/domain/site.go` |

## Площадки

| Код | Что это по документам проекта |
|---|---|
| **GrPP** | офисная площадка |
| **Luzhniki** | офисная площадка (в текстах ТЗ и ресерча — Лужники) |
| **GTP** | производственная площадка (завод, смены) |

Расшифровку аббревиатур GrPP и GTP в документах проекта мы не нашли — **не проверено**. «Для офисных сотрудников» в ТЗ импорт понимает как GrPP и Luzhniki (`scenario_xlsx_when.go`). Смены GTP в расписании пока не учитываются: у всех трёх площадок одни рабочие часы.

## Сценарий и конструктор

| Термин | Что значит |
|---|---|
| **Сценарий** | весь маршрут адаптации: блоки, шаги, команды, правила |
| **Черновик / версия** | HR правит черновик; «Опубликовать» создаёт новую неизменяемую версию. Каждый сотрудник идёт по своей версии |
| **Ветка** | ответ бота на конкретную кнопку или вариант: до двух реплик и действия, затем поток идёт дальше |
| **Общая ветка** | одна ветка на несколько кнопок (например, «если ответили 1 или 2») |
| **Действие** | что делает кнопка или ветка: завести обращение, связать с человеком, прислать файл, поставить отметку, ждать текст |
| **«Дальше →»** | кнопка, которой сотрудник листает сообщения блока без вопроса |
| **Опрос** | шаг с вопросами: выбор, несколько ответов, шкала, да/нет, текст |
| **Исход опроса** («После опроса») | правило, которое срабатывает по ответам: «если на вопрос 1 ответил 2 ЛИБО 3» или «+ если в вопросе 2 отмечено…» |
| **Флаг варианта** | код риска (F-код и серьёзность), привязанный к варианту ответа опроса. Сам по себе ставит сигнал риска, а не обращение |
| **Отмашка рекрутера** | отметка в карточке сотрудника, без которой шаги «по отмашке» не уходят (ТЗ r34, r36) |
| **Медиатека** | хранилище картинок и файлов по имени, с отдельным файлом на каждую площадку |
| **Заглушка** | запись медиатеки без файла: имя есть в ТЗ, а самого файла нет |
| **Команда** | слово с косой чертой, которое сотрудник пишет боту: `/help`, `/food`, `/hr` |
| **Правило сценария** | реакция на событие, а не на время: свободный вопрос без ответа (r69), напоминание об опросе (r70) |
| **Отчёт импорта** | сводка после загрузки Excel: сколько блоков, шагов, веток и список предупреждений со ссылкой на строку |
| **text_vy, вариант на «вы»** | второй текст шага для сотрудников, выбравших «вы». ТЗ написано на «ты», вариант на «вы» готовит ИИ, код проверяет |
| **Бейдж «ИИ — проверьте»** | метка на шаге, текст которого переписала модель и который HR ещё не вычитал |

## Ответы на вопросы (RAG)

| Термин | Что значит |
|---|---|
| **RAG** | способ отвечать по документам: сначала найти нужный пункт регламента, потом сформулировать ответ только по нему |
| **Корпус, база знаний** | документы, по которым бот отвечает: на демо синтетический регламент, локально — настоящие ПВТР и три презентации |
| **Пункт, фрагмент** | кусок документа, обычно один пункт регламента («6.1») или один слайд |
| **Гибридный поиск** | два поиска сразу: по словам (BM25) и по смыслу (bge-m3), результаты сливаются |
| **Реранкер** | вторая модель, которая перечитывает найденные пункты и ставит каждому оценку «отвечает ли он на вопрос» |
| **Порог (gate)** | минимальная оценка реранкера, при которой бот отвечает. Сейчас 0,2. Ниже — честный отказ |
| **Словарь сленга** | 19 групп разговорных слов («кусками», «проспал», «зп»), к которым дописываются термины регламента |
| **Переформулировка** | если порог не пройден, модель переписывает вопрос языком регламента, и поиск идёт ещё раз с защитами |
| **Ловушка** | вопрос, ответа на который в документах нет. Правильная реакция — отказ |
| **Инъекция** | попытка заставить бота нарушить правила («игнорируй инструкции»). Правильная реакция — отказ |
| **Галлюцинация** | ответ, которого нет в документах. Против неё — проверки кодом |
| **Golden set, отложенный набор** | наборы вопросов для замера качества. Отложенный составлен до настройки и честнее показывает новые вопросы |
| **Экстрактивный ответ** | бот отдаёт сам пункт дословно, без пересказа. Так он отвечает без модели или если модель не прошла проверку |

## Риски и обращения

| Термин | Что значит |
|---|---|
| **Флаг, F-код** | категория проблемы из `data/taxonomy.yaml`, от F0 (угроза жизни) до F10 (личные обстоятельства и здоровье). Полный список — [07-risk-and-escalation.md](07-risk-and-escalation.md) |
| **Сигнал риска** | отметка в карточке сотрудника, в зоне риска и в дайджесте. Обращения не создаёт |
| **Зона риска** | цвет сотрудника: зелёная, жёлтая, красная |
| **Обращение** | вопрос или проблема сотрудника, переданная человеку (HR, рекрутеру, HR-партнёру, СБ), со статусом и сроком ответа |
| **SLA** | срок, в который человек должен взять обращение и ответить |
| **Живой диалог** | состояние, когда сотрудник переписывается с человеком через бота, а вопросы не уходят в поиск по регламентам |
| **Конфиденциальное обращение** | F5 и F9: текст сотрудника скрыт, руководителю не показывается, F9 уходит в СБ |
| **Порог анонимности 5** | в обзоре и дайджесте не показываются темы и ячейки, где меньше пяти человек |
| **Индекс W** | индекс самочувствия по шкалам опросов, 0–100. Формула из ресерча, на реальных данных не откалиброван |
| **Дайджест** | сводка недели для руководителя подбора: темы, зоны риска, площадки, динамика, без имён |

## Роли

| Роль | Кто это |
|---|---|
| **Сотрудник** | новый сотрудник на адаптации. Живёт только в чате MAX, кабинета не видит |
| **HR, рекрутер** | работают в веб-кабинете: сотрудники, сценарии, обращения, база знаний |
| **HR-партнёр (HR BP)** | получает чувствительные обращения: конфликты, грубость, намерение уйти |
| **Руководитель подразделения** | руководитель сотрудника. Получает в MAX поводы встретиться 1:1 и смотрит страницу «Мои сотрудники» |
| **Руководитель подбора** | получает дайджест недели в MAX и смотрит «Аналитику» |
| **СБ** | служба безопасности. Получает F9 (коррупция, этика) |

## Техника

| Термин | Что значит |
|---|---|
| **MAX** | российский мессенджер, в котором живёт бот |
| **Long polling** | способ, которым бот получает сообщения из MAX: сам регулярно спрашивает «есть новое?». Не требует своего домена с сертификатом |
| **Подделка MAX** | имитация MAX внутри нашего кода. На ней идут тесты и демо-чат |
| **Демо-чат** | страница кабинета `/dev/chat`, где можно пройти путь сотрудника без телефона. Только в режиме разработки |
| **LLM, модель** | языковая модель, которая формулирует ответы. У нас T-lite-it-2.1 |
| **T-lite** | открытая модель Т-Банка, 8 млрд параметров, лицензия Apache-2.0 |
| **RunPod, под** | арендованная видеокарта в облаке RunPod. Наш под называется «hackaton» |
| **vLLM** | программа, которая запускает модель на видеокарте и отвечает на запросы |
| **T-one** | открытая модель распознавания русской речи, работает у нас локально на процессоре |
| **Сертификат Минцифры** | корневой сертификат «Russian Trusted Root CA». Без него API MAX не пускает |
| **Сид** | заливка синтетических демо-данных в базу |
