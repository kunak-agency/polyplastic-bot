# Контракты между частями (v0, каркас)

Это стартовые контракты для параллельной работы. Меняются только вместе с этим файлом.

## Порты (локально, только 127.0.0.1)

| Сервис | Порт |
|---|---|
| backend (Go, Fiber) | 8081, префикс `/api` |
| frontend (Vite dev) | 5173 |
| services/rag (FastAPI) | 8093 |
| postgres | 5437 → 5432 |

Занято соседями на этой машине: 8080 (API clinik), 5433–5436 (Postgres других проектов).

Имя compose-проекта: `polyplastic`.

## backend → services/rag

`GET /health` → `{"status":"ok"}`

`POST /ask`
```json
{"question": "когда можно в отпуск", "site": "GTP|GrPP|Luzhniki|null", "trace_id": "01J...",
 "address_form": "ty|vy|null"}
```
`address_form` необязателен, по умолчанию «вы». Нужен промпту `agency/prompts/rag-answer.md`.
→ 200
```json
{
  "answer": "string | null",
  "sources": [{"doc": "ПВТР", "clause_id": "6.7.8", "page": 14, "quote": "дословный текст"}],
  "confidence": "high|medium|low",
  "needs_escalation": false,
  "topic": "hr|legal|security|other",
  "abstain_reason": "no_source|below_threshold|routed_topic|null"
}
```
Правило: если `needs_escalation=true`, то `answer=null`, и бот показывает шаблон отказа из
UX-спецификации (п. 2.5). Проверку цитат (`clause_id` есть среди найденных чанков, `quote`
входит в текст чанка) делает сам rag-сервис до ответа.

`POST /flags` (может стоять заглушкой)
```json
{"text": "наставник третью смену не объясняет", "context": "pulse_d5|free_text|voice",
 "survey_question": "текст вопроса опроса, к которому относится ответ | null"}
```
`survey_question` необязателен.
→ `{"flags":[{"code":"F4","severity":2,"confidence":0.8}],"sentiment":"neg|neu|pos","quote":"..."}`
С 24.10 `/flags` работает на LLM (промпт `agency/prompts/flags-classify.md` v1, копия в
`services/rag/prompts/`). В ответе добавлено поле `"degraded": true|false`. `degraded=true` значит, что
LLM не задан, не ответил или дважды ответил не по схеме: `flags` тогда пустой, потому что текст
не размечен, а не потому что флагов нет. Код `F0`–`F10` берётся из таксономии, `severity` 1–3,
флаги с `confidence` < 0.3 отбрасываются. `quote` — дословная подстрока текста или `""`; у F10
и при телефоне, e-mail или паспорте в цитате она всегда пустая. Маршрут и порог решает backend по
`data/taxonomy.yaml`.

`POST /documents` (multipart: `file` — `.pdf|.pptx|.xlsx|.txt|.md` ≤ 25 МБ, `doc` — имя
документа, необязательно) → `{"doc_id","chunks","clauses","low_confidence_pages":[3]}`. Документ
с тем же `doc` заменяет предыдущий целиком. Ошибки: 415 формат, 422 пустой или битый файл,
413 размер. `GET /documents` → `{"items":[{"doc_id","doc","filename","kind","source",
"chunks","clauses","low_confidence_pages","uploaded_at"}],"total":N}`. Подробности —
`services/rag/README.md`.
⚠ У rag-сервиса нет авторизации: он слушает только loopback. Право HR загружать документы
проверяет backend, кабинет напрямую в rag не ходит. Документы пока живут в памяти процесса и
после рестарта пропадают.

Regex-триггеры (уволь*, взятк*, откат*, ударил*) живут в Go и срабатывают независимо от
этого сервиса.

## frontend → backend

Ошибки в формате clinik/toplivo: `{"error":{"code":"...","message":"...","traceId":"..."}}`.
`GET /api/health` → `{"status":"ok","db":"ok|down","rag":"ok|down"}`.

### v1 — итерация 1 (новички, сценарии, машина времени)

Общие правила: id — UUID-строки; даты — `YYYY-MM-DD`, время — ISO 8601 с зоной; `site` —
`GrPP|Luzhniki|GTP`; `day_offset` — целое, считается от D0 в календарных днях (перенос с
выходных делает планировщик); списки — `{"items":[...],"total":N}`. Авторизации в v1 нет.

Сотрудник (новичок):
```json
{
  "id": "uuid", "full_name": "Иванов Пётр (синтетика)", "phone": "+7…", "site": "GTP",
  "department": "Цех экструзии", "position": "Оператор линии",
  "manager_name": "…", "mentor_name": "…", "recruiter_name": "…",
  "start_date": "2026-11-03", "shift": "1|2|3|null",
  "scenario_id": "uuid", "scenario_version": 3,
  "address_form": "ty|vy|null", "consent": "given|declined|null",
  "connection": "invited|connected|stopped",
  "day": 12, "stage": "before|day0|week1|month1|probation|done",
  "invite_link": "https://max.ru/<bot>?start=inv_<token>",
  "last_activity_at": "…|null", "last_pulse": 2, "risk": "green|yellow|red", "risk_reason": "…|null",
  "open_tickets": 0
}
```
- `GET /api/newcomers?site=&q=&risk=` → список.
- `POST /api/newcomers` (поля карточки без вычисляемых) → 201 + сотрудник с `invite_link`. Это
  «Запустить адаптацию»: события таймлайна создаются сразу, по версии сценария на момент запуска.
- `GET /api/newcomers/{id}` → сотрудник.
- `GET /api/newcomers/{id}/timeline` → `{"items":[{"event_id","step_id","day_offset","title",
  "kind","fire_at","status":"scheduled|sent|answered|skipped|failed","answer":"…|null"}]}`.
- `POST /api/newcomers/{id}/time-travel` `{"day": 0}` → отправить все события по `day`
  включительно, которые ещё не ушли (с пометкой `[ТЕСТ]` в тексте), → таймлайн.

Сценарий:
```json
{"id":"uuid","name":"Завод GTP","sites":["GTP"],"version":3,"status":"draft|published",
 "active_newcomers":4,"updated_at":"…"}
```
Шаг сценария:
```json
{"id":"uuid","day_offset":-3,"time":"10:00","stage":"before","sites":["GTP"],
 "kind":"text|card|file|survey|task","title":"Знакомство",
 "text_ty":"…","text_vy":"…",
 "buttons":[{"label":"На «ты»","action":"…"}],
 "survey":{"scale":"1-10|1-5|yesno|choice","threshold":8,"questions":[{"text":"…","options":["…"]}]}|null,
 "condition":"…|null","work_hours_only":true}
```
- `GET /api/scenarios` → список; `GET /api/scenarios/{id}` → сценарий + `steps`.
- `PUT /api/scenarios/{id}/steps` (весь список шагов) → черновик.
- `POST /api/scenarios/{id}/publish` `{"comment":"…","apply":"new|active"}` → новая версия.
- `POST /api/scenarios/import` (multipart, Excel формата ТЗ) → сценарий-черновик. Пока Excel кейса
  нет, колонки «когда / повод / метка / макет / текст / обязательный / изображение» —
  предварительные, их сверим с файлом.

Уточнения v1 (по итогам фронта, 23.10):
- Тело `PUT /api/scenarios/{id}/steps` — `{"steps":[...]}`. Новые шаги приходят с `id`, который
  сгенерировал клиент (UUID). Сервер принимает такой `id`, а если `id` нет — создаёт свой.
- `PUT steps`, `publish` и `import` возвращают сценарий вместе со `steps`.
- `import`: поле multipart называется `file`, принимаются `.xlsx` и `.xls`.
- Пустой `sites: []` у шага или сценария означает «все площадки».
- `status: "draft"` при `version > 0` означает «есть неопубликованные изменения поверх vN».
- `POST /api/newcomers` без опубликованной версии сценария → 409 `scenario_not_published`.
  `scenario_version`, `address_form` и `consent` клиент не передаёт: первое фиксирует сервер,
  остальные два ставит бот.
- Машина времени не меняет `start_date` и `day`. Она только досрочно отправляет события,
  статусы которых становятся `sent`. В элементе таймлайна есть необязательное поле
  `"text": "…|null"` — текст, который ушёл в MAX, с пометкой `[ТЕСТ]`.
- `last_pulse` — `number|null`; `fire_at` — ISO с зоной площадки (`+03:00`).
- (сведение фронт↔бэкенд, 23.10) `text` в таймлайне есть у любого ушедшего события: у
  отправленного планировщиком — как ушёл, у машины времени — с `[ТЕСТ]`; у `scheduled` — `null`.
- Пополевые ошибки 422 лежат в `error.details[{field,code,message}]`; путь шага —
  `steps[N].<поле>`, где N — индекс в присланном списке. Кабинет показывает общее `message`
  и первое пополевое, а для `steps[N]` открывает этот шаг.
- Шаг `kind: "survey"` без `survey` (или с пустым списком вопросов) сервер не сохраняет —
  422 на весь `PUT …/steps`. Импорт строк «опрос» пока даёт `survey: null`, поэтому кабинет
  помечает такой шаг и предлагает «Настроить опрос» (шкала 1–10, порог 8, вопрос из текста).
- `publish.comment` на сервере необязателен; кабинет требует его сам (история версий).
- `POST /api/newcomers/{id}/time-travel` → 409, пока `connection != "connected"`: кабинет
  выключает кнопку и объясняет заранее, а не после отказа.

⚠ backend (итерация 1, 23.10) — что реализовано сверх или уточнено, поля не переименованы:
- Добавлен `PATCH /api/newcomers/{id}` `{"start_date":"YYYY-MM-DD"}` → сотрудник: перенос даты
  выхода, неотправленные события пересчитываются без дублей. В v1 его не было, а без него
  перенос даты не запустить из кабинета.
- `buttons[].action`: `""` или любой код — записать ответ (подпись кнопки уходит в `answer`
  таймлайна); `"link:<url>"` или `"https://…"` — кнопка-ссылка; `"skip"` — шаг `skipped`;
  `"human"` — не рисуется, «Спросить человека» и так последний ряд.
- `survey.questions[].options`: у `choice` — варианты ответа; у `1-10` и `1-5` — кнопки причин
  при оценке ниже `threshold` (пусто — четыре причины по умолчанию). Одна шкала на опрос:
  смешать 1–10 и да/нет в одном опросе (D+14 из UX-спеки) нельзя — это два шага.
- `POST /api/newcomers`: сценарий не для площадки новичка (непустой `sites` без неё) → 422.
  Ошибки валидации — 422 `VALIDATION_FAILED` с `details[{field,code,message}]`.
- `POST /api/newcomers/{id}/time-travel`: новичок не подключился к боту или бот выключен →
  409 `CONFLICT`; без согласия опросы не уходят и остаются `scheduled`; `day` — от −30 до 120.
- `POST /api/scenarios/import`: `.xls` (Excel 97–2003) → 422 с подсказкой «сохраните как
  .xlsx» — excelize читает только OOXML. Необязательное поле формы `name` (иначе имя файла).
  Колонки «обязательный» и «изображение» читаются, но пока не ложатся в шаг.
- `PUT …/steps` принимает и голый массив; `time` пусто → `10:00` в ответе.
- Знакомство (ты/вы) и согласие — системные сообщения бота, не шаги сценария.

Создание и удаление сценария (24.10, кнопка «Создать сценарий»; ux-spec 3.5):
- `POST /api/scenarios` `{"name":"…","sites":["GTP"],"from_scenario_id":"uuid|null"}` → 201
  сценарий-черновик (`version: 0`, `status: "draft"`) со `steps`. Без `from_scenario_id` — шагов
  нет. С ним — копия шагов **последней опубликованной версии** источника (источник ни разу не
  публиковался — его черновика) с **новыми** `id` шагов: таймлайны новичков источника копию не
  узнают. Источник не меняется; у копии своя история версий.
  - `name` обязателен (обрезается, до 200 символов) → иначе 422 `details[{field:"name"}]`.
  - Имя уникально без учёта регистра и крайних пробелов → 409 `scenario_name_taken`.
  - `sites` — коды площадок, повторы схлопываются; `[]` или нет поля — «все площадки»; чужой
    код → 422 `sites`. Кабинет при копии подставляет площадки источника, HR их меняет.
  - `from_scenario_id` не UUID или сценария нет → 422 `from_scenario_id`.
  - Импорт Excel (`POST /api/scenarios/import`) уникальность имени пока не проверяет.
- `DELETE /api/scenarios/{id}` → 204. Только черновик без публикаций (`version: 0`, версий нет)
  и без новичков (в любом статусе) — иначе 409 `scenario_not_deletable` (в `message` — почему).
  Нет сценария → 404. Удаляются сценарий и шаги черновика. Кабинет показывает «Удалить
  черновик» только при `version == 0` и `active_newcomers == 0`, с подтверждением.
- `POST /api/scenarios/{id}/import` (multipart, поле `file`, `.xlsx`) → 200 сценарий со `steps`:
  шаги файла **заменяют** черновик этого сценария, как `PUT …/steps`; имя и площадки сценария
  не меняются. Нужен пустому редактору («Загрузить Excel»). Ошибки файла — как у
  `POST /api/scenarios/import`; нет сценария → 404.

Плейсхолдеры в текстах шагов (`text_ty`, `text_vy`; подставляет бот при отправке):
- `{Имя}`, `{имя}`, `{name}` — имя новичка из карточки.
- `{start_day}` — день выхода относительно момента отправки, по часам площадки: «завтра», если
  D0 — следующий календарный день; «сегодня» — в сам D0; иначе «в понедельник, 26 октября».
  `{Start_day}` — то же с заглавной буквы, для начала предложения. Нужен шагам до выхода: D−1,
  перенесённый с выходного на пятницу, иначе обещал бы «завтра». Машина времени шлёт раньше
  срока — подстановка считается от фактической отправки. В сиде: D−1 «{Start_day} — ваш
  первый день. Как настрой?».
- Импорт Excel: строка с макетом «опрос» получает опрос по умолчанию — шкала `1-10`, порог 8,
  один вопрос из «текста» (пусто — из «повода»). Пометка кабинета «Настроить опрос» больше не
  нужна, но не мешает.

### dev — только `APP_ENV=development`

Маршруты под `/api/dev` вне development отвечают 404. В кабинете кнопка «Сымитировать
подключение» (панель машины времени) есть только в `pnpm dev` (`import.meta.env.DEV`); в
production-сборке её нет, а сервер с `APP_ENV=production` ответил бы 404.

- `POST /api/dev/simulate-start`
  `{"newcomer_id":"uuid","address_form":"ty|vy|null","consent":"given|declined|null"}` →
  сотрудник. Играет за новичка: в обработчик бота уходит `bot_started` с payload его
  приглашения (`inv_<token>`) от синтетического `user_id` (стабилен для новичка), затем — по
  желанию — нажатия «на ты/на вы» и согласия, как из long polling. После согласия бот сам
  досылает созревшие шаги (пакет D−3 идёт с паузами в фоне — машина времени в этот момент ждёт
  его). Нужен, чтобы показать машину времени без телефона: без подключения она 409.
  Ошибки: 422 — не UUID или чужие значения; 404 — новичка нет; 409 — бот выключен, приглашения
  нет или оно просрочено/занято другим аккаунтом.

- `POST /api/dev/simulate-message` `{"newcomer_id":"uuid","text":"…"}` или
  `{"newcomer_id":"uuid","payload":"h"}` → `{"status":"ok"}`. Играет за подключённого новичка
  текст или нажатие кнопки, как из long polling: так обращения показываются без телефона
  («Спросить человека» — payload `h`; сигнал F9 — текст со словом «откат»). Ошибки: 422 — нужно
  ровно одно из `text`/`payload`; 404 — новичка нет; 409 — бот выключен или новичок не подключён
  (сначала `simulate-start`).

- Демо-чат — только `APP_ENV=development` **и** бот на подделке MAX (нет `MAX_BOT_TOKEN`); с
  настоящим MAX маршруты отвечают 404. Подделка ведёт журнал диалога: исходящие бота, их правки
  (`Edit` и `AnswerCallback` с message — то же сообщение, `edited:true`), всплывающие уведомления
  (`AnswerCallback` notification — отдельная запись `from:"toast"`), «печатает» (5 с после
  `typing_on`, гаснет с новым сообщением). Входящие новичка в журнал пишут dev-хуки
  (`simulate-start` — «Начать» и нажатия ты/вы и согласия, `simulate-message`, `press`). Журнал
  в памяти процесса API: перезапуск его очищает. Страница кабинета `/dev/chat` есть только в
  `pnpm dev`.
  - `GET /api/dev/chat/{newcomer_id}` →
    `{"messages":[{"id":"mid.fake.7|in.8|toast.9","from":"bot|newcomer|toast","kind":"text|press|start","text":"…","format":"|markdown|html","buttons":[[{"text":"…","type":"callback|link|request_contact","payload":"…","url":"…"}]],"attachments":[{"type":"image|file|…","url":"токен подделки"}],"notify":true,"payload":"нажатая кнопка","reply_to":"mid","edited":false,"at":"…","edited_at":"…|null"}],"typing":false}`
    — только диалог этого новичка (его `user_id`/`chat_id`; до подключения — синтетический
    `user_id` из `simulate-start`). Ошибки: 422 — не UUID; 404 — новичка нет или не подделка.
  - `POST /api/dev/chat/{newcomer_id}/press` `{"message_id":"mid…","payload":"…"}` →
    `{"status":"ok"}` после обработки (как `simulate-message` с payload), но с `callback_id`,
    по которому ответ бота правит именно это сообщение. Ошибки: 422 — пустые поля; 404 — нет
    сообщения в диалоге новичка; 409 — новичок не подключён. Текст новичка — через
    `simulate-message`.
  Необязательное `"flag":"F0…F10"` (только вместе с `text`, сведение 24.10) — текст считается
  размеченным этим кодом, как ответ `/flags`, который бот пока не вызывает: риск, `HumanRequest` и
  обращение этой категории сразу. Так в dev показываются F4, F10 и др., у которых нет regex.
  Неизвестный код или `flag` без `text` → 422.

### v2 — итерация 3 (обращения)

Обращение создаётся в трёх случаях: кнопки «Спросить человека» и «Передать HR/рекрутеру» в боте,
ответ «Чего-то нет» в шаге «Проверка доступов», сработавший флаг (regex или `/flags`).
Существующий `HumanRequest` становится обращением или его источником, это решает backend.

```json
{
  "id": "uuid", "number": 1042,
  "newcomer_id": "uuid", "newcomer_name": "…", "site": "GTP", "day": 0,
  "category": "F0|F1|…|F10|question", "priority": "P0|P1|P2",
  "status": "open|assigned|human_active|resolved",
  "route": "hr|recruiter|manager|security|duty",
  "assignee_name": "…|null", "anonymous": false,
  "summary": "Сводка от Корсика: что случилось, 1–3 предложения",
  "quote": "цитата новичка|null",
  "sla_due_at": "…|null", "created_at": "…", "updated_at": "…",
  "notify_manager": false
}
```
- `GET /api/tickets?status=&site=&route=&mine=` → список; `GET /api/tickets/{id}` → обращение +
  `messages:[{"from":"bot|newcomer|staff","author":"…|null","text":"…","at":"…","internal":false}]`.
- `POST /api/tickets/{id}/assign` `{"assignee_name":"…","comment":"…"}` → обращение (`assigned`).
- `POST /api/tickets/{id}/reply` `{"text":"…","resolve":false}` → сообщение уходит новичку через бота
  с подписью «<Имя>, HR (по обращению #N):», статус становится `human_active`, а LLM для этого
  диалога ставится на паузу: пока обращение открыто, текст новичка идёт в обращение, а не в RAG.
  При `resolve:true` статус сразу `resolved`.
- `POST /api/tickets/{id}/note` `{"text":"…"}` — внутренняя заметка, в MAX не уходит.

### v3 — база знаний (итерация 4)

Кабинет ходит в rag **только через backend**: у rag нет авторизации, права HR проверяет backend.

⚠ Ограничение (ролей пока нет): все маршруты раздела пускают только при `APP_ENV=development`
или с заголовком `X-Operator-Token: <KB_OPERATOR_TOKEN>`; иначе 403 `PERMISSION_DENIED`. Пустой
`KB_OPERATOR_TOKEN` вне development закрывает раздел целиком. Кабинет токен не знает и не шлёт —
на стенде с `APP_ENV=production` его ставит прокси перед API (например, после basic-auth). Когда
появятся роли, проверка станет «роль HR», форма запросов не меняется.

Документ (строка таблицы):
```json
{"id": "uuid | corpus:<rag_doc_id>", "rag_doc_id": "6ec3792d15de4816", "doc": "Памятка (синтетика)",
 "filename": "memo.pdf|null", "kind": "pdf|pptx|xlsx|text|corpus", "source": "upload|corpus",
 "sites": ["GTP"], "version": 2, "status": "ready|needs_review|not_indexed", "indexed": true,
 "chunks": 14, "clauses": 22, "low_confidence_pages": [3], "size": 482133,
 "uploaded_by": "…|null", "updated_at": "…|null", "index_error": "…|null"}
```
- `source: corpus` — документ корпуса rag (`RAG_CORPUS_DIR`, сейчас синтетика): показывается, но
  версий и файла у backend нет, `size`/`uploaded_by` = null. Загрузка с тем же `doc` его заменяет.
- `status`: `ready` — в поиске; `needs_review` — в поиске, есть `low_confidence_pages` (страницы,
  для PPTX — слайды, на вычитку); `not_indexed` — файл сохранён, но rag его сейчас не видит.
  `indexed` — документ в индексе rag в момент ответа (rag не ответил — false, статус как
  сохранён). `sites: []` — все площадки (rag пока площадку не учитывает).
- `GET /api/documents` → `{"items":[…],"total":N,"rag":"ok|down"}`. Загруженные — из таблицы
  backend, сверенные с `GET /documents` rag (срок 3 с); корпус — из rag. Если загруженного в rag
  нет, backend в фоне перезаливает его (см. ниже).
- `POST /api/documents` (multipart: `file`; необязательно `doc` — имя ≤ 200 символов, иначе имя
  файла без расширения; `sites` — `GrPP,GTP` через запятую; `uploaded_by` — имя оператора, ролей
  нет) → 201 + документ. Документ с тем же `doc` — новая версия (`version+1`), прежняя сразу
  выходит из поиска (rag заменяет по имени). Проверки backend до rag: `.pdf|.pptx|.xlsx|.txt|.md`,
  непустой, ≤ `KB_MAX_UPLOAD_MB` (20; у rag 25), начало файла совпадает с расширением (`%PDF-`,
  zip, UTF-8) → 422 `VALIDATION_FAILED` с `details[{field:"file"}]`. Отказ rag по файлу
  (415/422/413) → 422 с нашим текстом («в файле не найден текст…»); rag не отвечает → 503, ответил
  не 2xx → 502, не уложился в `KB_UPLOAD_TIMEOUT` (3 мин) → 504 — в базе в этих случаях ничего не
  меняется. Индекс rag пересобирается синхронно: с hybrid ответ — до десятков секунд.
  Тело любого запроса API — до 26 МБ (fiber `BodyLimit`).
- `GET /api/documents/{id}/versions` → `{"items":[{"version":2,"current":true,"filename","kind",
  "size","sha256","chunks","clauses","low_confidence_pages":[],"uploaded_by":"…|null",
  "uploaded_at":"…"}],"total":N}`, новые первыми. 404 — нет документа (у корпусного версий нет).
- `POST /api/documents/ask` `{"question":"…","doc":"имя|null","site":"GTP|null"}` → ответ rag
  `/ask` как есть (`answer`, `sources[{doc,clause_id,page,quote}]`, `confidence`,
  `needs_escalation`, `topic`, `abstain_reason`) + `"from_doc": true|false|null` — есть ли цитата
  из документа `doc` (у XLSX `sources[].doc` = «имя / лист»). Обращение «вы», тот же конвейер, что
  у новичка. rag ищет по всей базе: фильтра по документу у него нет. Вопрос никуда не пишется (ни в
  `bot_questions`, ни в лог). `question` — 3…1000 символов, иначе 422. Ответ без источника → 502.
- `GET /api/knowledge/unanswered?site=&days=30&include_test=` → `{"items":[{"key":"пропуск
  родственник","title":"…","keywords":["пропуск","родственника"],"count":7,"newcomers":5,
  "reasons":{"no_source":6,"below_threshold":1},"examples":["…"],"first_at":"…","last_at":"…"}],
  "total":N,"questions":M,"since":"…"}`. Источник — `bot_questions` с `kind=abstain` и
  `abstain_reason` `no_source|below_threshold` (`routed_topic` — намеренная передача человеку, не
  пробел базы). Только вопросы с текстом (он хранится лишь при согласии) **и** у новичков, чьё
  согласие действует сейчас; `is_test` — только с `include_test=true|1`; `days` 1…365. Группировка
  без LLM: стоп-слова, грубый стемминг окончаний, одиночная связь «≥ 2 общих ключевых слова или
  Жаккар ≥ 0.5». `title` — самый типичный вопрос группы, `examples` — до трёх других, свежие
  первыми; всё обезличено: почта, телефоны, числа от 5 цифр, части ФИО самого новичка и слова с
  заглавной не в начале предложения → `[почта]`, `[телефон]`, `[номер]`, `[имя]`. До 50 групп,
  крупные первыми.

Хранение: rag держит загрузки в памяти. Метаданные, версии и **байты файлов** — в Postgres
(`kb_documents`, `kb_document_versions`, `kb_document_files` bytea): одна транзакция на
метаданные и файл, бэкап базы уносит и файлы, контейнеру API не нужен том. При старте backend ждёт
rag (паузы до 30 с) и перезаливает текущие версии, которых нет в `GET /documents` (сверка по
`doc_id`); то же в фоне, если список кабинета увидел пропажу. Не принял — `not_indexed` и
`index_error`.
